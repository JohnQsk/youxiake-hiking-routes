# 徙野 / Youxiake Hiking Routes

一个前期公开实验：把上海出发的一日徒步路线整理成可溯源的数据，并按**参考车程、徒步距离、累计爬升**比较。

- 静态网站：无需框架、无需后端、无需外部前端资源
- 种子数据：21 条入门路线 + 16 条进阶路线，来自游侠客 App 截图
- 进阶来源：App「一日线 · 进阶徒步」分类；活动 ID 用 youxiake-go 检索，数值再逐条回到官方详情页核对
- 官方核对：2026-11-05
- 数据来源：游侠客公开活动详情页；每条记录保留链接、核对日期和短摘录
- 非游侠客官方项目，不提供报名服务

## 网站

GitHub Pages：`https://johnqsk.github.io/youxiake-hiking-routes/`

本地运行：

```bash
python -m http.server 8000
```

打开 `http://127.0.0.1:8000`。请通过 HTTP 访问，不要直接双击 `index.html`，因为浏览器通常不允许 `file://` 页面读取 JSON。

## 页面

- `index.html`：首页，展示本周末单路线预览，并进入入门线 / 进阶线两个独立页面
- `beginner.html`：21 条入门线对照表，含本周末班期列与报名筛选
- `advanced.html`：16 条进阶线对照表，按车程、距离、爬升比较，并标注本周末班期、保留官方系列标签
- `about.html`：为什么做这个实验、数据方法与工具致谢

## 首页的本周末预览

`data/weekend-preview.json` 与 `weekend.js` 构成首页的大树王国（56151）展示试验：

- 只显示最近周末两天的班期状态和价格。
- 暂满日期不显示天气；只有可报名／确定成行日期才有天气块。
- 天气是 Open-Meteo 天目山附近网格预报，不是景区入口精确预报。
- 班期实时人数保持未知；不得用活动历史累计报名数替代。
- 这是 2026-11-05 的手动快照，不会自动刷新；全部路线可在两个对照表中筛选。

## 本周末班期

`data/weekend-availability.json` 是全站 37 条路线（21 条入门 + 16 条进阶）的本周末团期快照：

- 用 youxiake-go 的团期查询在 2026-11-05 11:45 抓取，只覆盖 11/07–08。
- 13 条可报名：入门 8 条（大树王国、梅坞古道、走马岗、九溪十八涧、埃码尖、穹窿山、江南小长城、荻港古镇·金盖山），进阶 5 条（高阳山、笔架山、虞山、姑苏旺七、杏梅尖）。
- 24 条本周末无班期；状态码 2（如大树王国 11/07）按暂满／不可报名处理。
- “确定成行”班次同样可以报名；暂满或无班期不显示为可报名。
- 只记录状态与班期价格，不记录余位或报名人数：接口的历史累计报名数不等于当前余位。
- 手动快照，不自动刷新；报名前仍需以官方页面为准。

## 已支持

- 按官方参考车程、徒步距离、累计爬升升降序排列
- 按路线名称或活动 ID 搜索
- 按车程上限、累计爬升上限筛选
- 多方案路线逐行切换，排序随当前方案更新
- 入门线与进阶线是两个独立页面，共用同一套搜索、排序与筛选
- 首页提供本周末预览，并进入两个路线合集
- 进阶页显示官方系列标签，并说明进阶不是官方难度评级
- 入门线与进阶线的表格都标注本周末 11/07–08 的班期状态与价格
- 两页共用同一份快照，并可按“可报名 / 不可报名”筛选
- 缺失值显示“未公开”，排序置底，不作为 0
- 入门 JSON 主数据及每方案一行的 CSV 导出；进阶数据只提供 JSON

## 数据边界

这两套数据都是 2026-11-05 的公开详情快照，不是游侠客全量路线库。

- **车程**是官方写明的单程或分段参考时间，不是实时导航时间。
- **距离和爬升**不等于完整难度；天气、路况和个人体能仍需另行判断。
- 进阶线的分类来自 App「一日线 · 进阶徒步」，不是官方安全评级；6km 的高骊山同样可能比 19km 的平缓线路更难。
- 官方写区间或“+”号时，表格按上限记录并在备注保留原文，不把它说成精确值。
- 多方案、多季节和接驳条件使用 `hiking_options` 表达，不强行合并成唯一数值。
- 未知字段为 `null`，不会用最高海拔、下降或某段接驳距离冒充总量。
- 班期、价格、天气默认不写进路线数据集；入门线与进阶页共用一份 11/07–08 的手动团期快照，明确记录抓取时间，不会自动刷新。
- 实际路线和安排以官方最新页面及出团通知为准。

## 数据结构

`data/routes.json` 顶层包含 `schema_version`、`checked_at`、`scope` 和 `routes`。

`data/advanced-routes.json` 沿用相同结构，另有 `tier: "advanced"` 和每条路线的 `series`（官方系列标签）。两页复用同一个表格脚本，通过 `<body data-routes>` 指定要加载的数据集。

`data/weekend-availability.json` 按活动 ID 保存全站 37 条路线本周末两天的 `status_code`、`status_label` 和 `price_cny`；没有班期时用空数组表示，不会把“无班期”写成 0。入门线与进阶页都通过 `<body data-weekend>` 加载这份快照。

每条路线主要字段：

| 字段 | 含义 |
|---|---|
| `id` / `source_url` | 官方活动 ID 与可回跳来源 |
| `name` / `short_name` | 官方完整标题与表格短名称 |
| `series` | 官方系列标签，仅进阶数据使用 |
| `departure_city` / `days` | 出发城市与活动天数 |
| `drive_time` | 排序用分钟数、区间及官方文字 |
| `hiking_options` | 路线方案、距离、累计爬升及备注 |
| `source_excerpt` | 支持数据理解的必要短摘录 |
| `checked_at` | 最近一次官方详情核对日期 |

区间车程使用 `min_minutes` 和 `max_minutes`；表格排序按下限，车程上限筛选按区间上限，避免把“2—2.5h”误纳入“≤2h”。
